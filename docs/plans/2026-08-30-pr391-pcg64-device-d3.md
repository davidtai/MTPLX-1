# PR #391 Exact PCG64 Device-D3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-optimized:subagent-driven-development (recommended) or superpowers-optimized:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove all three stochastic draft-sampling host decision boundaries while preserving the corrected variable-length M=4 verifier and the exact NumPy PCG64 request trajectory.

**Architecture:** A request-owned `PCG64UniformTape` clones the initial generator state, predraws a bounded float64 tape once, and advances the authoritative generator and logical cursor only as choices are consumed. A construction-installed fixed-D3 strategy reads three tape positions in one compiled MTP chain and returns the exact proposal supports needed by the unchanged host target-acceptance stage. The existing stochastic host lane remains the explicit control; the enabled tape lane has no runtime eligibility checks, environment reads, or fallback.

**Tech Stack:** Python 3.12, NumPy 2.4.4 PCG64, MLX 0.32.2, pytest, guarded Apple Metal execution.

**Assumptions and established outcomes:**

- Native Metal float64 failed the hard feasibility gate. The next gated route is a separately exact custom integer/software-binary64 selector; float32 is not an allowed fallback.
- Assumes the exact PR #391 lane is fixed native MTP depth three with physical verification width M=4, temperature 1, top-k 20, top-p 0.95, committed MTP history, and output allowance at most 16,384 — this lane will NOT support incompatible draft sources, penalties, constraints, adaptive depth, or other sampler geometry.
- Assumes the measured 1.268243-second draft-associated interval contains removable queue starvation — the stage will NOT be retained if same-work end-to-end A/B does not improve repeatably.
- Assumes every weighted `Generator.choice(..., p=...)` in NumPy 2.4.4 consumes the same single PCG64 uniform as the proven inverse-CDF rule for the reachable support sizes — the lane will NOT install for another NumPy version or bit generator without a new parity gate.

```python
from copy import deepcopy
from dataclasses import dataclass
import numpy as np

MAX_OUTPUT_TOKENS = 16_384
DRAWS_PER_CYCLE = 7


@dataclass
class PCG64UniformTape:
    rng: np.random.Generator
    values: np.ndarray
    cursor: int = 0

    @classmethod
    def build(cls, rng: np.random.Generator, *, max_output_tokens: int):
        if type(rng.bit_generator) is not np.random.PCG64:
            raise TypeError("exact device D3 requires numpy.random.PCG64")
        if np.__version__ != "2.4.4":
            raise RuntimeError("exact device D3 is pinned to NumPy 2.4.4")
        if not 0 <= int(max_output_tokens) <= MAX_OUTPUT_TOKENS:
            raise ValueError("exact device D3 supports at most 16,384 outputs")
        clone_bits = np.random.PCG64()
        clone_bits.state = deepcopy(rng.bit_generator.state)
        count = DRAWS_PER_CYCLE * (int(max_output_tokens) + 1)
        values = np.random.Generator(clone_bits).random(count, dtype=np.float64)
        return cls(rng=rng, values=values)

    def reserve_device_choices(self, count: int) -> int:
        offset = self.cursor
        self.rng.random(int(count))
        self.cursor += int(count)
        return offset

    def random(self) -> float:
        value = float(self.rng.random())
        self.cursor += 1
        return value

    def choice(self, values, *, p):
        value = self.rng.choice(values, p=p)
        self.cursor += 1
        return value
```

```python
@dataclass
class ExactDeviceD3:
    fn: Callable[..., tuple[mx.array, ...]]
    tape: PCG64UniformTape
    device_tape: mx.array
    vocab_size: int

    def run(self, hidden: mx.array, primary: int) -> DeviceD3Result:
        offset = self.tape.reserve_device_choices(3)
        outputs = self.fn(
            hidden, mx.array([[primary]]), self.device_tape,
            mx.array(offset, dtype=mx.uint32),
        )
        _eval(outputs)
        return _materialize_exact_d3_result(outputs, self.vocab_size)
```

The compiled function performs exactly three `rt.draft_mtp` calls. At each
level it calls `_device_exact_draft_choice` with
`device_tape[tape_offset + level - 1]`, feeds the selected token directly to
the following level, and returns three tokens plus three exact sparse proposal
supports. Before compile, promote the single QSA MTP-history cache for
`max_tokens + D3 headroom`, include those fixed leaves as compile
inputs/outputs, and warm/rollback once during installation. For the Qwen3.8
